# Day 39 — Interview Summary Generator

## What this day adds

Days 34–38 produce rich structured data — answer-quality tiers,
communication scores, confidence/stress signals, a weighted HR score,
an aptitude profile — but none of it is in a form a recruiter can
actually read in thirty seconds. This day is the final translation
layer: it takes Day 37's `HRInterviewScoreReport` and, optionally, Day
38's `AptitudeProfile` and Day 36's `InterviewConfidenceProfile`, and
turns them into strengths, weaknesses, cultural fit indicators, risk
flags, and a natural-language narrative.

## Reuse, not reimplementation

Every score reported on is read directly from existing outputs —
nothing here re-derives a signal:

| Deliverable | Reused from |
|---|---|
| Strengths / weaknesses | Day 37's `avg_relevance`, `avg_communication`, `avg_confidence`; Day 38's `overall_aptitude_score` |
| Cultural fit indicator | Day 37's per-answer `category` field, filtered to `teamwork_culture_fit` |
| Inconsistency risk flag | Day 37's `consistency.findings` (itself from Day 36) |
| Stress risk flag | Day 36's `overall_stress_score` (passed in directly, since Day 37's aggregate doesn't carry it forward) |
| Weak aptitude risk flag | Day 38's `overall_aptitude_score` |

This module's only new logic is **classification** (turning a number
into "strength"/"weakness" against a threshold) and **text generation**
(turning a classification into a sentence).

## Natural-language generation, stated honestly

"Generate natural-language report" means **template-based sentence
generation** — a fixed set of sentence templates selected by which
score band a number falls into, the same deterministic approach every
other module in this project uses. This is **not a generative language
model** — this project has no LLM integration anywhere, and this day
does not introduce one. The output reads naturally because the
templates were written to, not because anything was generated by a
model. Stated here rather than implied by "AI interview report
generator."

## Cultural fit indicators, stated honestly

The only direct signal this project has for "culture fit" is
performance on the single `teamwork_culture_fit` category question(s)
from the HR interview (Day 33's bank). This is a **narrow proxy** —
one or two answers about teamwork are not a real culture-fit
assessment, which would need far more (values alignment, work-style
preferences, references) than a rule-based text project can produce.
Reported as an "indicator," never a verdict — the generated sentence
says so explicitly.

## Risk flags, stated honestly

Each flag is a **mechanical threshold trigger** on an existing signal
(a vague/missing answer, a flagged inconsistency, elevated stress,
weak aptitude) — not a judgment about the candidate as a person. Every
flag carries the specific evidence behind it so a recruiter can check
the reasoning, not just trust a label.

## Thresholds

All score-band and flag thresholds are named module-level constants,
reasoned but **not calibrated against labeled hiring outcomes** — no
such data exists in this project, the same caveat stated on every
prior scoring day (34–38):

- Strong: ≥80 | Weak: <50 (middle band intentionally unlisted as
  neither strength nor weakness)
- Stress-elevated flag: ≥50 (Day 36's stress score)
- Combined score, when aptitude is supplied: 70% HR score + 30%
  aptitude score

## Deliverables

- `parsers/interview_summary_generator.py` — the AI interview report
  generator.
- `run_day39_summary_generator_demo.py` +
  `data/results/day39_sample_hr_summary_reports.json` — sample HR
  summary reports for three distinct candidate profiles (strong, weak,
  mixed), not just one happy-path example.
- `InterviewSummaryReport.to_dict()` / `to_narrative()` — the
  structured summary template, both as JSON and as readable text.

## Verification

18 new tests (`tests/test_interview_summary_generator.py`), covering
band classification, strength/weakness thresholds, cultural fit
(present and absent), every risk-flag trigger individually, combined
scoring with and without aptitude, and full-report generation.
`pytest` itself isn't installable in this build environment (no
network access), so these ran via the same assert-based Python runner
used since Day 35. Full project regression (313 tests, including Day
36/37/38's own suites that this module imports from) passed clean with
zero regressions.

Demo run across three profiles: strong candidate scored 77.4 (Good,
zero risk flags), weak candidate scored 43.2 (Weak, 3 risk flags),
mixed candidate scored 61.6 (Moderate, 2 risk flags) — three built-in
sanity checks confirm the strong candidate outscored the weak one,
landed in a different performance band, and surfaced fewer risk flags,
not just three isolated numbers that happen to look right.

## Not done here (left for a future day)

- Wiring this into an actual end-to-end pipeline that runs Days
  33→39 automatically from a single interview session — each engine
  is currently called and composed manually in the demo script.
- A real generative-language summary (an LLM call) — this project has
  no LLM integration anywhere; template-based generation was used
  consistently instead.
- Calibrating thresholds against real hiring outcomes — no labeled
  data exists in this project.
